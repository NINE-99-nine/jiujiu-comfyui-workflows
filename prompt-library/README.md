# prompt-library · 优质提示词库 / 风格库

> 本目录存放**高质量、可直接复刻的成品提示词与配套资料**，按「工作流/模型」与「内容」分类管理，方便日后"翻到就复刻"。
>
> **与工作流侧的分工（勿混）**：`workflows/<模型>/prompting.md` 管「**书写格式规范**」、`guide.md` 管「**工作流使用指南**」——那边是"**怎么写、怎么提交**"；本目录是"**写好的成品长什么样、怎么照着复刻**"。

## 一、分类机制（重要：以后一律按此归置，禁止乱放）

顶层按**两类**组织，保持架构受控成长：

### A. 工作流 / 模型风格库 —— `<模型>/`
每个模型一个子目录，存放该模型专属的优质提示词风格库。

```
prompt-library/
├── krea2/          # krea2 风格库（见其 README：一个风格一份 NN_风格.md）
├── anima/          # anima 风格库（见其 README）
├── qwen_image2.1/  # qwen_image2.1 风格库（见其 README）
├── moss/           # MOSS-Image 提示词库（见其 README：多人图 Scene JSON 等）
└── ...
```
- 每个 `<模型>/` 目录自带 `README.md`，写明**该模型的分类机制 + 风格索引**。
- 风格文档命名 `NN_风格名.md`（两位序号前缀 + 中文风格名）。

### B. 通用内容词库 —— 内容维度
横跨工作流、按内容分类的词条库（非单一模型专属）。

```
prompt-library/
└── ...
```

## 三、归置规则（禁止乱放）

1. **模型专属风格** → 放对应 `<模型>/` 子目录，一个风格一份 `NN_风格.md`，并更新该目录 README 索引。
2. **横跨模型的通用词条** → 放内容维度子目录。
3. **书写格式 / 工作流使用指南** → **不放这里**，归 `workflows/<模型>/prompting.md` 与 `guide.md`。
4. 新增顶层目录前，先在本 README 登记，保持架构受控成长。
5. 负面提示词一律不入库（内嵌工作流，不交付）。

## 四、与工作流侧的关系

- 书写方法论 / 格式：`workflows/krea2/prompting.md`、`workflows/krea2/guide.md`
- 成品范式与复刻资料：**本目录**
- 执行：`execution/EXECUTION.md`
