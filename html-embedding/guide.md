## ★ 总纲：整体思维 + 图1+html 合成（2026-08-31 作者定稿，P0）

**核心思想：两个过程不能割裂。先构思好最终的整幅效果，再反推图1 怎么出、html 怎么排版。不是先出一张图、第二步看着图硬凑。**

### 1. 整体思维

- 设计图1（AI 出图）时就要想到后期 html 文本编辑：**先构思最终整幅效果 → 基于这个效果设计合理的图1 内容 + 配套 html**。
- 图1 里**与画面绑定、耦合性高的文字**（工牌金铭牌、顶部大标题美体字等）→ 由 AI 模型生成（krea2 中英文都能渲）；**耦合性低的文字**（案例列表、联系信息、中文正文、卖点句）→ 用 html，避免 AI 渲错中文。

### 2. 图1 + html 的两种合成路径

| 方式 | 做法 | 适用 |
|---|---|---|
| **A. 图1 上加文字** | 直接在原图上叠 html 文本，**画布 = 图1 尺寸** | 想保住原图分辨率时 |
| **B. 图1 上做画布拓展** | 用 html 在图1 基础上拓展画布，形成**拼接/半包围/左右包围/全包围**结构，**图1 占比约 80%**（按需调整） | **推荐**——保住人物细节 |

### 3. 图1 生成要点（别浪费 AI 出图性能）

- AI 出图本就受限（性能/速度/模型能力），**不要刻意缩小人物占比制造大量无用留白**——那会降低人物精度/细节感。
- **正确做法**：图1 让**人物为主、细节丰满**（占主体），补充文字空间靠 html **画布拓展**，而不是让图1 主动留白。

### 4. html 编辑 + 与图片交融（侵入式过渡 + 多字体碰撞）

- **交接处侵入式设计**：文字可以**突破 html 底色、入侵图片里一点点**（参考《风骚律师》海报），视觉更美观。顺序 = 文本 → 交接处 → 图片。
- **均衡**：交接处重叠部分，图片1 上没有重要内容（别遮脸/手/主视觉），但也**不过度留白**（浪费图1 性能）。
- **文字直接印在画面上**（带轻投影/描边保证可读），**不要裹成不透明纯色块**（作者批：纯色块 + 单一字体 = 空洞丑陋）。
- **多字体/颜色碰撞**（参考图美感来源）：手写草书签名 + 印刷衬线小字 + 书法大标题 + 星星/划线/印章装饰 + 红黑金配色 + 红圆勾案例图标。字号有大跳跃、疏密有致。

### 5. 图片是主题，html 是辅助

- 图片占主体（约 80%），html 文字只做点缀/补充，不能喧宾夺主。单调的 html 撑不起图的内容。

## 完整流程

```
1. ComfyUI 出底图（anima 流程，分辨率按海报比例选；提示词内预留文字区：
   横屏写 subject placed on the right side, empty clean space on the left for text overlay；
   竖屏写 empty space at top/bottom for title text）
2. 写 HTML：存 D 盘 tmp（严禁 C 盘），html,body 宽高 = 目标成品尺寸，overflow:hidden
3. Edge headless 截图合成
4. 交付前把成品重命名为有意义中文名（作者习惯7，硬性）
```

## Edge headless 截图命令（关键）

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 --window-size=<W>,<H> --screenshot="D:/.../成品.png" "file:///D:/.../poster.html"
```

- **window-size 必须等于 HTML body 尺寸**，否则截图被裁/留白
- file:// 加载本地图片 OK；中文文件名/路径 OK
- 输出行 `xxx bytes written to file` = 成功；无关 ERROR 噪音（QQBrowser importer、sync network）可忽略
- Chrome 同样可用（`/c/Program Files/Google/Chrome/Application/chrome.exe`）
- 单张约 3-8 秒；多张可连续调用（一条命令 && 串联）

## 布局铁律（作者明确要求）

- **文字绝不遮挡图片主体**。三种安全布局：
  - 左侧栏：520px 文字面板 + 右侧大图（横屏主力）
  - 上下条：顶部题字条 + 中部图 + 底部条（竖屏/带鱼屏）
  - 画卷题跋式：带鱼屏上下题字条 + 中间画卷
- 角色名超大字覆盖式（人设图/角色卡，作者 2026-08-09 定稿）：图占右中主体，嵌字全部集中左侧数据栏（**禁止左右双侧嵌字**），主角名荧光巨字横跨图与嵌字区左侧制造张力——「文字不遮主体」的明确例外
- 图上边缘可放小字（刊头/特供标签），必须渐变底衬（scrim）且不压主体
- **中心区域不放文本**；文字放侧栏/上下边缘；绝不让文字盖住主体

## 嵌字内容原则（作者明确要求）

- **嵌字必须与画面主题强相关**，不能图文无关（"要体现出画面的主题"）
  - 例：宫殿走廊图 → 弹幕夸仪态/问宫殿、小黄车卖同款红绳蝴蝶结
  - 例：守岸人海岸图 → 旅行社广告推"海岸线自驾""黑海岸灯塔日落线"
- **嵌字世界观铁律（最高优先级）**：嵌字内容必须贴合画面内容与作品世界观——禁止"理工男文案"配萌图。BA 角色配社团日常口吻（游戏开发部「今日也在摸鱼……啊不是，在写代码！」）；守岸人配旅行广告（AAA 黑海岸旅行社、联系人「秋*师傅」）；角色特色物可带货/做菜单项（红绳蝴蝶结→小黄车同款；蛋糕→甜单）
- **文案要有梗、不呆板**：俏皮评语、押韵口号、数字细节（限量 500 件已抢 437 件、立减 520）
- 评分条四连（魅力/丝袜/清纯/足部…）用多了会审美疲劳——主动换菜单、弹幕、路线表等新形式
- 制作人署名：默认写「作者」（除非另有要求）；古风海报可配朱砂印章「作者」

## 嵌字风格样张法（成套项目先定风格，防整套返工）

作者做多图成套项目（人设图/系列海报）时，**先做 HTML 风格样张选定，再出底图**（扬·人设图验证）：

1. 一个 HTML 页排布 3-4 种风格样张（1×2 或 2×2），角色图位置用占位块（灰块/网格+「立绘位」字样），嵌字用**真实内容**（名字/属性/简介）
2. Edge headless 截图（如 1600×1020），MEDIA: 交付，附风格对比表（气质/契合点/推荐倾向）
3. 作者选定后可提布局修正——忠实执行并回写本技能
4. 样张命名：`主题_风格样张_日期.png`，存 D 盘 tmp

**审美铁律（作者原话：「你的 html 审美还是有待提高」）**：做终端/界面类风格要**真实质感**——真实终端窗口逻辑（标题栏 -□×、命令行、文件路径、状态栏）、克制的辉光、统一间距节奏、box-drawing 边框精准；**禁止贴标签堆元素、禁止大杂烩**。

## 批量条漫拼版（10+ 格级，走 Pillow 不走 HTML）

15 张级批量漫画用 HTML 拼版成品 PNG 会到 25MB+，**改用 Pillow 拼版**：`scripts/manga_panel.py`（3×5 网格、金色描边、每格底部对白条、标题+署名区、JPG 输出 3-5MB）。

流程：批量提交 N 个 prompt 入队（每格独立设 [23] + graphToPrompt + POST /api/prompt）→ **批量轮询**（脚本遍历所有 prompt_id 查 /history，打印 DONE/ERROR 明细，含 error 状态检测，勿静默失败）→ 拷贝成品改名 p01~p15 → 改模板 DIALOG/标题后运行。详见 `references/multi-panel-manga.md`。

- 底图 1536×1016 模板自动缩 2/3 → 1024×677；对白条 56px 高，单条 ≤18 字
- 中文字体用 C:/Windows/Fonts/msyh.ttc（只读，不写入 C 盘）
- 剧情型批量图：每格对白按剧情递进写，全篇定调统一

## 防溢出技巧（poster5 教训：左下角文字被挤出画面）

- 侧栏用 `display:flex; flex-direction:column` + `overflow:hidden`
- 长文本块设 `flex:1 1 auto; min-height:0; overflow:hidden`
- 固定元素（标题/评分/署名）设 `flex-shrink:0`
- 总原则：内容必须能在固定高度内放下，宁可缩小字号/行距，不可溢出

## Pitfalls

1. **跨午夜输出目录切换（真实踩坑）**——ComfyUI 输出按 YYYY-MM-DD 分目录。23:59 提交、00:0X 完成 → 成品落新一天目录。用 `ls -t` 按修改时间找最新文件，别死等提交时的日期目录。
2. **文字溢出画面**——侧栏/文字区用 flex + overflow 控制（见防溢出技巧），内容超长会静默溢出。
3. **窗口尺寸必须 = body 尺寸**，不一致会裁图或留白。截图前用 `ls` 检查成品尺寸是否等于画布。
4. **嵌字与画面脱节是返工主因**——见"嵌字内容原则"。
5. **条漫对白气泡例外**（2026-08 走光三幕验证）：漫画风的气泡/拟声词是画面语言，允许叠图（放角落、白底黑边、带尾巴），不受"文字不遮主体"铁律约束；但旁白/菜单等非漫画元素仍走侧栏/上下条。拟声词用日式（パサッ/じゅわ/ぴくん），`-webkit-text-stroke` 描边 + 旋转斜置。
6. **Comfy Desktop 输出目录可能漂移到 C 盘（真实踩坑，2026-08-06）**：即使 settings.json 的 outputDir 指向 F 盘，data-location.json 的 `mode=local-appdata` 会使运行时 `--output-directory` 解析到 C 盘。**提交前必查 system_stats → argv → --output-directory**；若指向 C 盘：生成后立即拷贝 D 盘并**删除 C 盘本次生成文件**，并告知作者需在 Comfy Desktop UI 改共享路径（配置修改需重启应用，勿擅自重启）。
7. **带鱼屏（4:1）不要套侧栏式**——宽度太窄放不下；用上下题字条/题跋条布局。
8. **批量多图**（视频章节插图）：提示词可复用模板改角色串/场景/分辨率；嵌字文案按每图角色世界观单独写，别套同一套文案。
9. 交付文件必须重命名（主题+版本+日期），禁止自动编号/临时名（作者习惯7）
10. 不要用 vision 自我检查画面内容——出图直接交付，作者自己看
11. 底图用 file:// 绝对路径，HTML 与截图脚本放 D 盘（作者厌恶 C 盘写入）
12. **受限/无桌面会话 headless 截图不可用（8-25 实踩）**：DSH 后台/服务进程会话下，Chrome/Edge 无法创建 crashpad 子进程（`OpenProcess 0x5`），`--headless` 截图必然失败（加 `--no-sandbox` 亦无效）。**此类环境直接走 PIL 后端合成**（自写 PIL 排版，或 `scripts/` 的 Pillow 拼版），别费时试浏览器。衬线中文用 `C:\Windows\Fonts\STZHONGS.TTF`，衬线英文用 `georgia.ttf`。
