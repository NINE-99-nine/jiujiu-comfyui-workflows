# flux2 图像正常编辑 · 使用守则（guide v1.0）

> 本守则与 `flux2图像正常编辑.json`（UI 格式，skill 内备份，**实际出图不用它**）+ `flux2图像正常编辑_api.json`（API 格式，**实际出图用这个**，由引子 `flux2图像正常编辑_api.py` 调用）配套。
>
> ⚠️ **分工**：`flux2图像正常编辑.json`（不带 API 后缀）仅作 skill 内备份/分享给人类参考；实际调用靠 `flux2图像正常编辑_api.py` + `flux2图像正常编辑_api.json` 这套。两者不要混用。
>
> 🔒 **两文件边界**：引子只读同 basename 的 API 版 json，UI 版物理不可达。通则见主 skill 核心铁律 0a。

## ⚠️ 两个 flux2 工作流的区别（关键！）

作者有两个 flux2 编辑工作流，**别用混了**：

| | **flux2图像放大编辑** | **flux2图像正常编辑** |
|---|---|---|
| 原理 | SAM3.1 遮罩定位 → **Inpaint Crop** 裁剪放大局部 → flux2-klein 精修 → **Stitch** 拼回原图 | **不裁剪**，整图作 reference 喂给 flux2-klein 全图重绘/多图融合 |
| 适用 | 图大但**改动范围小**（换脸/换表情/局部修改）→ 裁剪放大给模型足够精度展开手脚 | 正常整图编辑/多图参考融合 → 精度"凑合即可" |
| 图输入 | 最多 2 图（图1主 + 图2参考） | 最多 **3 图**（图1主 + 图2/图3参考） |
| 关键节点 | SAM3_Detect(2)/InpaintCrop(15)/InpaintStitch(24) | imageIndexSwitch(1309)/ReferenceLatent 子图(1317/1318/1319) |
| 输出尺寸 | 与原图同尺寸 | 由 [1306] 分辨率决定 |

**一句话**：改动范围小 → **放大编辑**（拖拽裁剪给精度）；改动范围大/整体重绘/多图融合 → **正常编辑**。

## 原理（flux2-klein 整图/多参考编辑）

1. 主图（图1，[1326]）经 [1320] 缩放。
2. [1319] 子图（Reference Conditioning）：VAEEncode(1319:740) 把主图编码 → ReferenceLatent(1319:741 pos / 1319:739 neg) 把编辑词 [1305] 与主图 latent 变成 conditioning → 喂 KSampler(1313)。
3. KSampler(1313) 用 flux2-klein 9B 编辑，[1306] 分辨率决定出图大小。
4. VAEDecodeTiled(1324) → SaveImage(1325)。

**多图参考**（图2/图3）：每图经各自缩放 → VAEEncode → ReferenceLatent，**conditioning 层层串接**（图2 接主图输出，图3 接图2 输出），最终接入 KSampler——实现"图1图2人物放图3场景/图1人物穿上图2服装"等多参考融合。

## 分辨率规则（动态 1.2~1.6M，作者 8-31 定）

- **[1306] 分辨率在 1.2~1.6 百万像素之间动态选**，**图多了就低**（接近 1.2M，防爆显存）。
- **分辨率比例**按参考图定：
  - 只有图1、简单编辑 → 与图1保持一致
  - 图1图2的人物放到图3的场景 → 参考图3（或自设一个合理比例）
  - 万能图像编辑模型（非简单重绘），比例自由度比放大编辑大——不必死扣某图。
- 建议：**单图 1.5~1.6M，双图 ~1.4M，三图 ~1.2M**，8 的倍数、贴目标比例。

## 提示词编写指南（作者 9-1 案例提炼）

> flux2-klein 是图参考模型——**直接看图，不靠文字复述参考图的特征**。提示词核心：**准确指向目标 + 约束其余保持不变**。

**两条铁律：**
1. **准确指向**：说清是「图X中的某某」，别用模糊的「图X中的人物」。用具体特征/部位锁定目标。例：
   - 换发色：`将图1中人物的头发从白色改为蓝色`（明确起点终点，别用模糊'变为'）
   - 指定换面：`将图1中人物的面部替换为图2中人物的面部。仅替换面部，不改变服装。`
2. **保持其余不变**：补一句「人物姿态、表情、服装、场景、光线等**其余全部保持不变**，画风与质感与原图保持一致」——给模型定义重绘边界。

**多图参考**：图2/图3只作参考，**不要用文字复述其外貌**（模型会直接看图）。提示词写「以图2人物替换图1人物」即可，外貌交给图参考。


**分辨率要不要贴参考图比例 —— 看任务类型（9-1 作者定）：**
- **单主体编辑（换脸/换衣/换发色/局部改）**：主体就是图1，**贴图1比例**出图。例：图1是 3072×864（3.556超宽幅），就用超宽幅（如 2304×648）。**不要用方图**——Klein 能吃夸张宽幅，贴参考图比例才能保住原构图。
- **角色参考生成新图**：当图1/图2只是给角色参考，最终生成的是**两个角色的另一张全新图**（非原图主体编辑），此时**没有贴某图比例的需求**，按新图构图自由定比例。

## 提交方式（黑盒引子，agent 只传参数）

引子自动完成 图片上传（本地 → ComfyUI input 目录）→ 内存拼 API（不落盘，多图时动态注入被绕过的子图分支）→ 递交 `execution/comfy_submit.py` → 校验 `node_errors:{}` → 轮询 → 拷贝成品到 `_work/flux2图像正常编辑/` → 打印一行 JSON。

```bash
# 简单编辑（单图）
python flux2图像正常编辑_api.py --img1 "f:/x.png" --prompt "把图1的人换成白发红瞳少女" --w 1344 --h 1344 --name edit1
# 多参考（图1图2人物放图3场景）
python flux2图像正常编辑_api.py --img1 "f:/x.png" --img2 "f:/y.png" --img3 "f:/z.png" --prompt "让图1图2的人物出现在图3场景里" --w 1024 --h 768 --name multi
```

- `--img1` 主图 + `--prompt` 编辑内容基本必传
- `--img2`/`--img3` 可选（多参考），传了就自动注入对应 reference 子图并串接
- `--w/--h` 按上图规则定（动态 1.2~1.6M）
- 返回一行 JSON：`{"kind":"image","prompt_id":"…","file":"…","size":"…"}`

## 注意事项

- **两文件边界**：引子只读 API 版，UI 版仅供人类参考（铁律 0a）。
- **多图注入是接线注入**（引子在内存展开被绕过的子图分支），与放大编辑同思路——不依 UI 的 GroupIgnoreManager（API 无组概念），逻辑等价。
- **模型大**（flux2-klein 9B），多图大分辨率易爆显存 → 按上图"图多则低分辨率"原则。
- 暂时不提供 `--seed`（模板 KSampler 有 seed 但引子未暴露，如需固定可后期加）；改 prompt/图/分辨率可破缓存。
